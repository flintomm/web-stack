A frank look at what this stack actually costs, where tools step on each other's toes, and what's still missing. Pricing as of May 2026 — verify before you commit.

Today's bill → ~$11 / yr Realistic ceiling → ~$45–60 / mo

Right now, you're spending ~$11/yr on the Porkbun domain and riding free tiers everywhere else — Netlify, Cloudflare, Firebase Spark, Resend Free, GitHub Free, Umami self-hosted, Search Console. The ceiling kicks in once you outgrow free tiers: Netlify Pro ($20) + Railway Hobby ($5) + Resend Pro ($20) + a small DO droplet ($4) lands around ~$50/mo. Firebase Blaze can spike unpredictably — set a Google Cloud budget alert.

Overlaps & redundancies

— where two tools do the same job —

Cloudflare DNSvsPorkbun DNS LOW · BY DESIGN

Porkbun's "free DNS" is literally Cloudflare under the hood. If you set Cloudflare nameservers on your Porkbun domain, you bypass Porkbun's DNS panel and manage records directly in Cloudflare — unlocking caching, WAF, page rules, and Workers.

Verdict — pick one and stick to it. Cloudflare for full features, Porkbun for "I just want it to resolve."

Netlify FunctionsvsRailway / Fly MEDIUM

Both can run backend code. Netlify Functions are serverless (cold starts, 10s timeout); Railway/Fly run always-on processes. People reach for Functions because their frontend is already on Netlify, then hit timeout walls.

Verdict — Functions for tiny webhooks. Anything stateful, long-running, or with a real DB → Railway.

Firebase HostingvsNetlify LOW

Firebase ships its own static hosting. It's fine, but Netlify has better Git integration, deploy previews, and edge functions. Most people only use Firebase Hosting because they're already in the Firebase console — not because it's better.

Verdict — keep Firebase for Auth + Realtime DB only. Let Netlify handle the static frontend.

RailwayvsFlyvsDigitalOcean HIGH · PICK ONE

All three host backend apps. Three accounts, three bills, three sets of mental overhead. You probably don't need all three — most projects only need one.

Verdict — default to Railway. Use Fly only if multi-region latency genuinely matters. DO only when you want to learn Linux/admin or run something Railway can't.

UmamivsGoogle Search Console NOT REDUNDANT

Easy to confuse — both deal with "who visits the site." But: Umami answers "who came and what did they do" (live traffic, referrers, pages). Search Console answers "what does Google think of my site" (crawl errors, indexed pages, search queries that led to clicks).

Verdict — keep both. They're complementary, not duplicates.

Cloudflarecould replacemost of this stack WORTH KNOWING

Cloudflare offers Pages (Netlify-like, unlimited bandwidth), Workers (Lambda-like), R2 (S3-like, no egress fees), D1 (SQLite), KV, Email Routing, and registrar. A Cloudflare-only stack is real and many devs run it.

Verdict — not telling you to switch. But know it exists, and consider Pages next time Netlify credits get squeezed.

Gaps worth filling

— what's missing, and a recommendation —

// gap 01 Error monitoring

Right now, when production breaks, you find out from a user. Error monitoring catches uncaught exceptions, stack traces, and slow requests in real time.

Pick: Sentry (free up to 5K errors/mo). Drop-in for Vite/React, takes 10 min.
// gap 02 Object storage

For user uploads, images, exports — anything Firebase Storage isn't already handling. Cheaper at volume than Firebase.

Pick: Cloudflare R2 ($0 egress, 10GB free). You already use Cloudflare.
// gap 03 Uptime monitoring

Is the site actually up right now? You don't have a pager. A simple ping every 60s tells you when something falls over.

Pick: UptimeRobot (free, 50 monitors) or BetterStack.
// gap 04 Secrets management

Firebase keys in URLs, plaintext passwords — past audit findings. A vault or env-var manager fixes the blast radius.

Pick: Doppler (free tier) or just lean on Netlify/Railway env vars + .env.local for dev.
// gap 05 CI / testing

Netlify builds prod, but nothing runs your tests on push. GitHub Actions covers this without leaving GitHub.

Pick: GitHub Actions (free 2,000 min/mo on private repos, unlimited on public).
// gap 06 Backups

If Firebase Realtime DB gets corrupted or someone fat-fingers a delete, what's the recovery plan? Right now: none.

Pick: Scheduled Cloud Function exporting to Cloud Storage. Or move to Firestore (built-in scheduled backups).
