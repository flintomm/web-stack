01 Build & frameworks

— what you run on your laptop to turn source files into shippable bundles —

Bundler

A tool that reads your scattered source files (JS, CSS, images, components) and outputs the smaller, optimized files a browser actually downloads. Without one, the browser would have to fetch every file individually — slow.

Appears in: Vol. 01 / Vite card

Dev server

A tiny web server that runs on your laptop while you’re writing code. Serves your site at localhost:5173 (or similar) and reloads when you save a file. Not what users hit in production.

Appears in: Vol. 01 / Vite card

HMR (Hot Module Replacement)

When you save a file, the dev server swaps just the changed code into the running page — no full reload, no losing what you typed in a form. The reason modern dev feels instant.

Appears in: Vol. 01 / Vite card

SPA (Single-Page App)

One HTML file. JavaScript swaps the visible content as you click around — no full page reloads. Snappy, but the page is blank until JS runs, which hurts SEO and slow connections.

Appears in: Vol. 01 / Vite card

Compiler

Turns source code in one language into a different form that can actually run. gcc compiles C into machine code; Vite/Astro compile .jsx + .css into the .html/.js a browser eats.

Appears in: Vol. 02 / Rosetta translation

JAMstack

JavaScript + APIs + Markup. The pattern: pre-built static HTML/CSS/JS served from a CDN, calling APIs only when the page needs live data. No server rendering pages on demand. Cheap, fast, mostly cacheable.

Appears in: Vol. 01 / Netlify card

02 Source, version control, domains

— the names, ledgers, and pointers that make a site real —

Repo (Repository)

The folder Git tracks. One per project. Contains your code plus every change ever made to it (branches, history, who-did-what). “Push to the repo” means upload your changes.

Appears in: Vol. 01 / GitHub card

Version control

A system that records every save as a snapshot — restorable, shareable, branchable. Git is the dominant one; GitHub is where you put a Git repo so others can see it.

Appears in: Vol. 01 / GitHub card

Webhook

A URL one service calls when something happens. Push to GitHub → GitHub fires Netlify’s webhook → Netlify rebuilds. Replaces “poll every 5 minutes to see if anything changed.”

Appears in: Vol. 03 / Wiring diagram

Domain registrar

A company licensed by ICANN to sell you a domain name. Porkbun, Namecheap, Cloudflare. You pay yearly — if you stop, the name goes back on the open market.

Appears in: Vol. 01 / Porkbun card

WHOIS / WHOIS privacy

WHOIS is the public registry of who owns each domain (name, address, email). WHOIS privacy hides your real info behind a proxy — mandatory in 2026 if you don’t want spam.

Appears in: Vol. 01 / Porkbun card

DNS (Domain Name System)

The internet’s phonebook. Translates example.com into 93.184.216.34 (the actual IP your computer connects to). Every page load starts with a DNS lookup.

Appears in: Vol. 02 / DNS Lookup step

Nameserver

The DNS server that’s authoritative for a domain — the source of truth for “where does example.com live?” You set yours at the registrar; usually you point them at Cloudflare.

Appears in: Vol. 04 / Cloudflare DNS overlap

A record / CNAME

DNS entry types. An A record points a name directly at an IPv4 address (104.21.x.x). A CNAME points a name at another name (which then resolves to an IP).

Appears in: Vol. 03 / Wiring diagram

TXT record

A DNS field that holds arbitrary text. Used for site-ownership verification (Google, Apple), email auth (SPF, DKIM, DMARC), and other “prove you control this domain” checks.

Appears in: Vol. 01 / Search Console card

TLS / HTTPS / SSL

Encryption between browser and server — the padlock in the URL bar. SSL is the old name, TLS is the current name, HTTPS is HTTP wrapped in TLS. Free now thanks to Let’s Encrypt; auto-issued by every modern host.

Appears in: Vol. 01 / Cloudflare card

03 Hosting & infrastructure

— where your code actually runs, and what each tier hands you —

Static hosting

A server that hands out files only — no code runs on the server when a request comes in. Cheap, fast, can’t do anything dynamic without JS in the browser. Netlify, GitHub Pages, Cloudflare Pages.

Appears in: Vol. 01 / Netlify card

CDN (Content Delivery Network)

A network of servers in many cities that cache copies of your static files. A user in Tokyo gets the file from a Tokyo server, not California — faster and cheaper. Cloudflare runs ~300 of these.

Appears in: Vol. 01 / Cloudflare card

WAF (Web Application Firewall)

A filter sitting in front of your site that blocks malicious requests (SQL injection attempts, scrapers, known-bad bots) before they reach your server. Cloudflare ships a basic one for free.

Appears in: Vol. 01 / Cloudflare card

PaaS (Platform as a Service)

They give you the OS, runtime, networking, SSL. You give them your code (or a Dockerfile). Middle ground between dumb static hosts and bare VPSes. Railway, Fly.io, Heroku, Render.

Appears in: Vol. 02 / Rental Ladder, “Railway” row

VPS / droplet

VPS = Virtual Private Server, a slice of a physical server you control completely. Droplet is what DigitalOcean calls theirs (other vendors say “instance,” “node,” or just “VM”). You pick the OS, install the software, manage security.

Appears in: Vol. 01 / DigitalOcean card

Container / Docker

Your app + everything it needs (libraries, system tools, config) packaged into one isolated, runnable unit defined by a Dockerfile. Same container runs the same way on any host — your laptop, Railway, AWS — which is why everything supports it.

Appears in: Vol. 01 / Railway card

Procfile

A one-line file (literally named Procfile, no extension) that tells a PaaS what command to run. E.g., web: node server.js. Heroku invented it; most PaaSes accept it as a fallback when there’s no Dockerfile.

Mentioned in chat — not currently in the manual

Edge functions

Code that runs inside the CDN, in the same data center as the cached files — close to the user. Faster than a single origin server but limited in size, runtime (often V8/JS only), and disk access.

Appears in: Vol. 01 / Netlify card

Serverless / cold start

Serverless: a function that runs only when called, then sleeps. You pay per invocation, not per uptime. Cold start: the first call after a sleep is slow (hundreds of ms to seconds) because the runtime has to spin up. Subsequent calls are fast until it sleeps again.

Appears in: Vol. 04 / Netlify Functions overlap

Build credits / build minutes

How PaaS and static hosts meter compute. Each git push triggers a build that consumes minutes (or “credits”). Run out, builds queue or fail until next month or you upgrade. Bandwidth and function invocations are usually metered the same way.

Appears in: Vol. 01 / Netlify card

04 Backend & data

— the parts that hold state, identify users, and send mail —

API (Application Programming Interface)

A service’s public “control panel” — a defined set of URLs and message formats that other code can call. Most modern APIs are HTTP/JSON. When you say “the Stripe API,” you mean the URLs Stripe lets you POST to.

Appears in: Vol. 03 / Wiring diagram

SDK (Software Development Kit)

An official client library that wraps an API in your language. You call firebase.signIn(email, pass) instead of fetch() with the right headers and body. Saves you from re-reading the docs.

Appears in: Vol. 03 / “SDK · realtime sync”

BaaS (Backend as a Service)

Auth + database + storage + push notifications, bundled as one product. You don’t run a server, you call SDKs from the frontend. Firebase and Supabase are the standards. Trades flexibility for “don’t spend two weeks wiring this up.”

Appears in: Vol. 01 / Firebase card

Realtime database

A database that pushes updates to subscribed clients automatically. When one user adds a row, every connected app sees it within milliseconds — no polling. Powers chat, collaborative docs, multiplayer state, live dashboards.

Appears in: Vol. 01 / Firebase card

Auth (Authentication)

Proving who a user is. Email + password, OAuth (“sign in with Google”), magic links, passkeys. Distinct from authorization, which is what they’re allowed to do once you know who they are.

Appears in: Vol. 01 / Firebase card

Transactional email

Single emails triggered by an event in your app: password reset, signup confirmation, receipt, alert. Distinct from marketing email (newsletters to a list). Different deliverability rules, different vendors usually.

Appears in: Vol. 01 / Resend card

SMTP (Simple Mail Transfer Protocol)

The 1982 protocol email travels over. Resend, Mailgun, Postmark all spit out SMTP under the hood — you just call their nicer HTTP API instead of speaking SMTP yourself.

Appears in: Vol. 02 / Rosetta translation

05 Networking & the request lifecycle

— the steps every page load takes between your laptop and the server —

IP address

The numeric “phone number” of a machine on the internet. IPv4 looks like 104.21.42.18, IPv6 looks like 2606:4700:.... DNS is what lets you type a name instead of digits.

Appears in: Vol. 02 / DNS Lookup step

TCP handshake

A three-step “are we both here, can we talk” exchange before any actual data flows. SYN (“hello?”) → SYN-ACK (“hi, I hear you”) → ACK (“great, let’s talk”). Happens once per TCP connection.

Appears in: Vol. 02 / TCP Handshake step

TLS handshake

After TCP is up, both sides exchange cryptographic keys so the rest of the conversation is private. Happens once per HTTPS connection. The server’s certificate is checked here — that’s where the “your connection is not private” warning comes from.

Appears in: Vol. 02 / TLS / HTTPS step

HTTP GET

The “send me this resource” request method. Most page loads and image fetches are GETs. Other common methods: POST (send data, e.g. a form), PUT (replace), DELETE (remove).

Appears in: Vol. 02 / HTTP GET step

Cache

A copy of something kept somewhere faster to read than the original. Browsers cache images. CDNs cache HTML. CPUs cache RAM. The pattern: store the slow-to-fetch thing close by, refresh occasionally.

Appears in: Vol. 02 / Rosetta translation, “CDN” row

06 Hardware

— the physical parts every “cloud” service is renting you a slice of —

CPU / RAM / disk

The three storage tiers of any computer. CPU: the chips that compute. RAM: working memory — fast, but loses everything on power-off. Disk (HDD / SSD): long-term storage — slower than RAM, keeps its contents forever.

Appears in: Vol. 02 / Hardware Rental Ladder

L2 cache

Tiny, ultra-fast memory built into the CPU itself. The CPU pulls hot data here so it doesn’t have to wait on slower RAM. A CDN’s edge cache is the same idea, scaled up to whole websites.

Appears in: Vol. 02 / Rosetta translation, CDN row

NIC (Network Interface Card)

The chip in your computer that talks to the network — ethernet port or wifi radio. Both your laptop and a cloud server have one; both work the same way. The cloud just rents you access to theirs.

Appears in: Vol. 02 / Rosetta intro

SSH (Secure Shell)

Encrypted command-line access to a remote machine. The “I’m just gonna log in and fix it manually” tool. ssh user@server.com drops you into a terminal as if you were sitting at that machine.

Appears in: Vol. 01 / DigitalOcean card

07 Cost & billing

— the words on every pricing page, translated —

Free tier vs. trial

Free tier: unlimited time, limited usage. Use it forever within the cap. Trial: unlimited usage, limited time — usually 7 to 60 days, then you must pay or your stuff stops working. Always read which one the vendor means.

Appears in: Vol. 01 / Fly.io card

Egress fees

What cloud providers charge you to send data out of their network — e.g. serving an image to a user’s browser. AWS S3 charges $0.09/GB; Cloudflare R2 charges $0. Often dwarfs the storage cost itself.

Appears in: Vol. 04 / R2 gap

Spend cap / budget alert

A hard limit on what you’ll be charged. Pay-as-you-go services without one can surprise you with $1,000 bills if you go viral for an hour. Set it explicitly, every time.

Appears in: Vol. 01 / Firebase card warning

Pay-as-you-go

You pay for exactly what you use, by the second/GB/request. No flat fee. Great when usage is small, dangerous when it isn’t — pair with a spend cap. The default model for AWS, GCP, Fly.io, Firebase Blaze.

Appears in: Vol. 01 / Fly.io card

08 Insight & SEO

— observing what the world is doing with your site —

Indexing / crawling

Crawling: Google’s bot fetching your pages and following links. Indexing: storing them in its search database so they can appear in results. A page can be crawled but not indexed (low quality, duplicate, blocked).

Appears in: Vol. 01 / Search Console card

Cookie banner

That popup asking permission to track you. Required by EU law (GDPR) when you set tracking cookies. Avoidable if your analytics tool doesn’t set cookies in the first place — that’s the whole point of Plausible/Umami/Fathom.

Appears in: Vol. 01 / Umami card

SEO (Search Engine Optimization)

The practice of getting pages to rank well in search results. 80% of it: clear writing, fast load, descriptive titles, no broken links, mobile-friendly. The other 20% is where the snake oil lives.

Appears in: Vol. 01 / Search Console card

Self-hosted

Running open-source software on your own server (a VPS, usually) instead of paying for the SaaS version. More control, more responsibility — if it falls over at 3 a.m., you’re the one paged.

Appears in: Vol. 01 / Umami card
