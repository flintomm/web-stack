Why Why this exists

Most “modern web stack” diagrams are vendor logo soup — pretty pictures, no prices, no relationships. This is the version that should exist: every service named, every price verified, every relationship drawn. The web didn’t need another logo grid, it needed a field manual.

Who Who it’s for

Anyone shipping their second or third website who keeps colliding with the same questions: do I need Netlify or Railway? Why is Cloudflare in front of everything? What does Firebase actually replace? If you’ve hand-rolled three landing pages and you’re about to build something with users, this is for you.

Sources How the prices were verified

Every dollar figure was checked on the vendor’s public pricing page in May 2026. Free-tier limits, trial windows, and overage warnings all come from the same source. If a number looks stale, the date in the header is when it was last refreshed — the open issue tracker on GitHub is the place to flag drift.

License Use this however

Code is MIT. Words are CC0 / public domain — copy them into your own slide deck, onboarding doc, or napkin. Attribution is appreciated but not required. If you fork it and adapt it for your own stack, the more concrete maps in the world, the fewer logo soups.

Honest disclosures What’s on the diagram vs. in production

The diagram is opinionated — it shows the tools that earn their place in a real working stack, not necessarily the tools any one project happens to be running on launch day. Some nodes (Vite, Firebase) earn their spot from private projects; others (Astro, Cloudflare, Railway, Resend, GitHub Pages) you can find in public repos. Umami is recommended as the self-hosted analytics layer; spin it up when you actually need traffic data, not before.
